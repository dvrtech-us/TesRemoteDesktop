# Configuration

Settings are read only through `settings::setting` (`src/settings.rs`), which calls `decisions::settings::resolve_setting`. For each of the eleven names (`HTTPS_HOST`, `CF_TOKEN`, `ACME_EMAIL`, `ACME_STAGING`, `VIDEO_ROOT`, `STREAM_HEIGHT`, `INPUT_MODE`, `LOG_LEVEL`, `FFMPEG`, `NO_WGC`, `BYPASS_IFACE`) the first non-blank value wins: a value this process wrote (`POST /config`, Fit screen, `--https-host`), then the real environment `TESREMOTE_<NAME>`, then the real environment `TESLAPC_<NAME>`, then `.env` `TESREMOTE_<NAME>`, then `.env` `TESLAPC_<NAME>`. A blank or whitespace-only value counts as unset. A non-blank value is returned unchanged, so `NO_WGC=1` stays exact. Setting keys from `.env` are not copied into the process environment, which is what keeps a real `TESLAPC_` variable ahead of a `.env` `TESREMOTE_` variable. Unknown `.env` keys are still copied into the process environment when that key was not already set, and the later file overrides the earlier one. Both locations are still read: the `.env` next to the executable, then `paths::env_file()` (the config folder: `%ProgramData%\TesRemoteDesktop\.env` on Windows, `$XDG_CONFIG_HOME/tesremotedesktop/.env`, default `~/.config/tesremotedesktop/.env`, on Linux).

`GET /config` returns `httpsHost`, `acmeEmail`, `videoRoot`, `logLevel`, `streamHeight`, `inputMode`, `version`, and `cfTokenSet`. It never returns the token. `public_config_json` has no token field.

`POST /config` is `application/x-www-form-urlencoded`. `apply_config_body` writes each saved setting as a `TESREMOTE_` line and removes the `TESLAPC_` line for that same setting. Every other line, including comments and unknown keys, stays. A blank `cfToken` is not written, so a stored token line, including `TESLAPC_CF_TOKEN`, stays. The response is `{ "saved": true, "restartNeeded": true }` when host, token, or email was written. `routes::config_post` and Fit screen also call `settings::set_setting`, so the next read in this process sees the new value.

Live keys, applied without a restart: `TESREMOTE_VIDEO_ROOT`, `TESREMOTE_LOG_LEVEL`, `TESREMOTE_STREAM_HEIGHT`, `TESREMOTE_INPUT_MODE`. A valid stream height also bumps the capture epoch. The height must be `240`–`2160`. Log level accepts `error`, `warn`/`warning`, `info`, `debug`/`verbose`, or `0`–`3`.

The Settings page is `tesremotedesktop/assets/config.html`. The 480/720/1080 buttons apply on tap with a `POST /config` of only `streamHeight` and show the result in `#msg`. A saved height that is not 480/720/1080 shows `Current: <h>p` with no button active. `streamHeight` is not part of Save settings. Save sends only fields (`httpsHost`, `acmeEmail`, `videoRoot`, `logLevel`, `inputMode`) that differ from the last successful `GET /config`, plus `cfToken` when typed. It is disabled until the first load succeeds, and with nothing changed it shows `Nothing to save.` and sends nothing. A new read-only Fit screen field under Stream resolution says: "The Fit screen button on the main screen sets both the PC's real display resolution and the stream resolution to suit the screen you tap it on. It picks the supported PC mode closest in shape that is at least as large as that screen, so the picture is sharp and black bars are small. TesRemoteDesktop does not restore the previous resolution afterwards." Fit screen can also write `TESREMOTE_STREAM_HEIGHT`. Hotspot buttons `POST /hotspot` with `on=1` or `on=0`.
